抽出・集计・突合：三大数据处理模式

抽出・集计・突合：三大数据处理模式

本章讲解日本业务系统中三个最核心的数据处理概念——抽出（筛选）、集计（汇总）、突合（核对），并给出对应的 COBOL 实现代码。这三个模式是 COBOL 批处理系统的基石。

1. 概念总览

在日本 IT 行业（尤其是银行、保险、物流、政府等大型机业务系统）中，数据处理工作几乎都可以归纳为三类基本操作：

术语 读音 含义 对应中文 对应英文 类比 SQL
抽出 ちゅうしゅつ 从大量数据中筛选出符合条件的记录 抽取、筛选 Extract / Select SELECT ... WHERE
集计 しゅうけい 对数据分组汇总、统计合计 汇总、统计 Aggregate / Summarize GROUP BY + SUM
突合 とつごう 两组数据相互对照、核对差异 核对、对账 Reconcile / Match JOIN + 差异检查

三者的关系：

记忆技巧：

  • 抽出 = 「抽」出来 → 从多到少，筛选
  • 集计 = 「集」起来「计」算 → 从散到合，汇总
  • 突合 = 「突」在一起「合」对 → 两份数据核对

2. 抽出（筛选）

2.1 概念

抽出是从输入数据中，按指定条件筛选出满足要求的记录，写入输出文件。不满足条件的记录被丢弃。

典型场景：

  • 从全量客户数据中抽出「本月新签约的客户」
  • 从交易流水中抽出「金额超过 100 万的记录」
  • 从库存数据中抽出「库存低于安全库存的商品」

2.2 处理流程

  3. 用计数器统计输入总数与抽出数

3. 集计（汇总）

3.1 概念

集计是对数据按某个键（维度）进行分组，计算各组的合计、件数、平均等统计值。

典型场景：

  • 按部门集计销售额
  • 按月份集计交易笔数与金额
  • 按商品类别集计库存数量

3.2 处理流程

关键前提： 集计要求输入数据已按集计键排序（SORT 或预先排序），这样才能用「键变化检测」实现分组。

4. 突合（核对）

4.1 概念

突合是将两组数据按某个键（突合键）相互对照，检查是否一致，找出：

  • 一致的记录
  • 仅左侧存在的记录（如：有订单无发货）
  • 仅右侧存在的记录（如：有发货无订单）
  • 键相同但内容不同的记录（如：金额不符）

典型场景：

  • 销售数据与收款数据突合，找出未收款交易
  • 订单数据与发货数据突合，找出漏发
  • 系统数据与银行流水突合，日终对账

4.2 处理流程（双文件匹配）

4.3 COBOL 示例代码

需求： 将订单文件与发货文件突合，找出未发货订单、无订单发货、金额不符。

要点：

  1. 预读：先各读一条，进入循环
  2. 归并比较：用 EVALUATE TRUE 分四种情况处理
  3. 键小者前进：ORD-ID < SHP-ID 说明订单侧无匹配，读订单下条
  4. 键相等：核对内容（金额），一致计数，不一致记录差异
  5. 文件结束：一侧结束则另一侧剩余全部为「仅单侧有」

小结

模式 核心操作 COBOL 关键语句 前提条件
抽出 条件筛选 READ + IF + WRITE 无
集计 分组汇总 READ + 键变化检测 + 累加 输入需按键排序
突合 双文件匹配 双 READ + 归并比较 两文件均按键排序

掌握这三个模式，就掌握了 COBOL 业务系统开发的核心思维。它们对应数据处理的三类基本操作：筛选、聚合、匹配。
